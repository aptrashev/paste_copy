# Продукт и требования

## Цель

Пользователь вызывает панель глобальной горячей клавишей, находит ранее скопированный фрагмент и возвращает его в текущее приложение за несколько секунд, не переключая рабочий контекст.

Первая аудитория — люди, которые регулярно переиспользуют текст, ссылки, изображения и файлы в нескольких desktop-приложениях: разработчики, дизайнеры, авторы и специалисты поддержки. Персональные сценарии не создают разные подсистемы; все они используют одну историю, поиск и повторную вставку.

## Основной сценарий

1. Пользователь копирует данные обычной командой ОС.
2. Приложение проверяет политику приватности и локально сохраняет допустимые представления clipboard item.
3. Пользователь нажимает настраиваемую глобальную горячую клавишу.
4. Панель открывается на активном дисплее, фокус поиска доступен с клавиатуры.
5. Пользователь выбирает результат и вставляет его с исходным форматированием или как plain text.
6. Если автоматическая вставка недоступна, приложение оставляет значение в системном clipboard и явно показывает ручной fallback.

## Функциональные требования MVP

| ID | Требование | Проверяемый результат |
| --- | --- | --- |
| FR-001 | Захватывать text/plain, HTML, RTF, изображения, URL и списки файлов, сохраняя несколько представлений одного item. | Fixture каждого типа проходит capture → storage → clipboard round-trip; неподдержанный тип не ломает monitor. |
| FR-002 | Проверять secret/transient markers, лимиты и правила до записи содержимого на диск или в поисковый индекс. | Запрещённый fixture отсутствует в БД, blob store, FTS и логах. |
| FR-003 | Дедуплицировать только полностью идентичные наборы representations и не захватывать собственную запись при повторной вставке. | Одинаковый plain text с разными HTML/RTF остаётся разными clips; повтор полного набора обновляет metadata; paste не создаёт новый clip. |
| FR-004 | Показывать локальную историю с превью, типом, временем и доступным приложением-источником. | Новая допустимая запись появляется без перезапуска; исчезнувший исходный файл помечается недоступным. |
| FR-005 | Открывать и скрывать компактную панель глобальной горячей клавишей; поддерживать keyboard-only навигацию и Escape. | Сценарий выполняется без мыши на macOS 13+ и Windows 10 22H2/11. |
| FR-006 | Искать по разрешённому тексту и metadata с фильтрами по типу и приложению, где источник доступен. | Релевантный результат находится в базе из 50 000 записей в пределах NFR-001. |
| FR-007 | Восстанавливать clipboard и выполнять rich/plain-text paste; при запрете инъекции предоставлять copy-only fallback. | Получатель получает ожидаемое представление либо пользователь видит однозначный fallback без потери данных. |
| FR-008 | Удалять одну запись, очищать историю, устанавливать/снимать простой флаг `retention_protected` и применять retention без удаления защищённых данных; удалять orphaned blobs. | После vacuum/GC нет ссылок на удалённые payload, а записи с `retention_protected` сохранены. |
| FR-009 | Позволять временно приостановить захват и явно показывать состояние pause. | Во время pause payload не materialize/read; после resume monitor продолжает работу. |
| FR-010 | Исключать приложения по стабильному platform identifier там, где ОС позволяет определить источник. | Fixture от исключённого приложения не сохраняется; при отсутствии API UI не обещает защиту. |
| FR-011 | При запуске определять capabilities и permissions, объяснять деградацию и давать путь к исправлению. | Отказ в macOS Accessibility, системном key store или Windows input из-за UIPI приводит к предсказуемому режиму, а не к silent failure. |
| FR-012 | Работать как single-instance tray/background app, опционально запускаться при входе и корректно завершать workers. | Второй запуск активирует существующий экземпляр; enable/disable autostart проверяется после reboot/login. |

## Нефункциональные требования MVP

| ID | Требование |
| --- | --- |
| NFR-001 | На эталонном наборе 50 000 записей: появление панели p95 ≤ 200 ms, локальный поиск p95 ≤ 100 ms. Методика и эталонное железо фиксируются перед beta. |
| NFR-002 | Чтение крупных payload, нормализация, шифрование, запись, FTS и GC не блокируют UI thread; очереди ограничены и имеют backpressure. |
| NFR-003 | Любая сборка, способная хранить реальные пользовательские данные, шифрует SQLite/FTS и внешние blobs; master key хранится в системном key store и не попадает в config/логи. Упрощённый storage разрешён только изолированному automated-test profile с синтетическими fixtures и недоступен production/release configuration. |
| NFR-004 | Clipboard payload, поисковые строки, ключи и полные пути не попадают в telemetry, crash metadata и production logs. |
| NFR-005 | Основной сценарий выполняется с клавиатуры; focus order, screen-reader labels и системные настройки reduced motion/contrast учитываются. |
| NFR-006 | Ошибка одного clipboard item или adapter не останавливает monitor; пользователю доступен безопасный copy-only режим. |
| NFR-007 | Миграции версионированы, транзакционны и проверены на upgrade; при ошибке исходная база не уничтожается, приложение предлагает экспорт diagnostics без payload. |
| NFR-008 | Обновления и release artifacts подписаны; неподписанное или неверно подписанное обновление отклоняется. |

## После MVP

- `P1-001`: полноценное избранное с отдельным UX и постоянные коллекции; MVP-флаг `retention_protected` остаётся простой политикой хранения.
- `P1-002`: Paste Stack с последовательной вставкой.
- `P1-003`: расширенные фильтры и настраиваемые правила retention.

## Не входит в MVP

Cloud sync, мобильные клиенты, shared collections, OCR, AI-рекомендации, MCP/automation API, копирование содержимого исходных файлов внутрь vault, app stores и Linux целиком, включая X11 и Wayland.

## Допущения

- Приложение локальное и однопользовательское; аккаунт не требуется.
- MVP работает одним процессом: UI event loop плюс ограниченные фоновые Rust workers.
- Для file list сохраняются URI/пути и metadata, но не содержимое файлов. Исчезновение файла — штатное состояние.
- Эвристический поиск паролей/токенов выключен по умолчанию из-за ложных срабатываний; системные secret/transient markers и app exclusions обязательны.
- Поддержка означает проверенную конфигурацию macOS 13+ или Windows 10 22H2/11 из [PLATFORM_SUPPORT.md](PLATFORM_SUPPORT.md).

## Принятые платформенные решения

- MVP поддерживает macOS 13+ и Windows 10 22H2/Windows 11.
- Linux отложен после MVP и не получает adapter, package, CI job или support claim до нового ADR и platform spikes.
- Поставка MVP — прямые подписанные установщики: notarized/signed `.dmg` и code-signed `.msi`; Mac App Store и Microsoft Store вне scope.
- Real-data builds всегда используют зашифрованное хранилище. Test-only исключение изолировано, принимает только синтетические fixtures и не включается в production/release configuration.

## Открытые решения

После platform spikes остаётся утвердить числовые бюджеты memory, idle CPU, disk quota и maximum item size. До измерения они не являются обещанием release.

## Критерий успеха MVP

Все `FR-*` и `NFR-*` имеют пройденный тест или документированное ограничение платформы; нет известных P0/P1; основной сценарий работает на реальных macOS 13+ и Windows 10 22H2/11 машинах; установщики подписаны, а реальные данные никогда не сохраняются незашифрованными.
